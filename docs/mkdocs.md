# Настройка MkDocs с Material темой и GitHub Pages через Docker

## Введение

Это руководство описывает полный процесс настройки системы документации на MkDocs с Material темой, работающей в Docker, с автоматической публикацией на GitHub Pages через GitHub Actions. Инструкция подходит для macOS с процессором Apple Silicon M-серии.

## Структура проекта

Проект размещается в папке ~/Projects/mkdocs. Базовая структура выглядит так:
docs/ — папка с исходными файлами документации.
.github/workflows/ — папка с конфигурацией GitHub Actions.
В корне проекта находятся файлы Dockerfile, docker-compose.yml, mkdocs.yml, requirements.txt, Makefile и .gitignore.

### Файл Dockerfile

Создаётся в корне проекта. Он описывает образ для запуска MkDocs в контейнере. Используется базовый образ python:3.11-slim. Рабочая директория внутри контейнера — /app. Сначала копируется requirements.txt и устанавливаются зависимости через pip. Затем копируются все исходники. Открывается порт 8000. Команда запуска — mkdocs serve с привязкой к 0.0.0.0:8000.

### Файл requirements.txt

Содержит зависимости Python. Для работы нужны mkdocs версии 1.6.1 и mkdocs-material версии 9.5.34.

### Файл docker-compose.yml

Описывает сервис mkdocs. Собирается образ из текущей директории. Пробрасывается порт хост-системы 8001 на порт контейнера 8000, чтобы избежать конфликта с другими сервисами. Монтируется текущая папка в /app внутри контейнера для автоматического обновления файлов. Устанавливается переменная окружения PYTHONUNBUFFERED=1.

### Файл mkdocs.yml

Это главный конфигурационный файл. В нём указываются название сайта, описание, автор и URL для публикации. Настраивается тема Material с палитрой цветов indigo. Добавляются полезные функции темы: вкладки навигации, секции, интеграция оглавления, подсказки при поиске, кнопка копирования кода. Язык устанавливается русский. Используется плагин поиска. В секции markdown_extensions подключаются расширения для admonitions, подсветки кода, вкладок, таблиц и других элементов. В навигации указываются страницы: Главная, Начало работы, API Reference.

### Файл .gitignore

Исключает из репозитория папку site с собранным сайтом, кэш Python, файлы Docker, системные файлы macOS и настройки IDE.

### Файл Makefile

Содержит удобные команды. Команда serve запускает сервер разработки через docker-compose up. Команда build собирает статический сайт в папку site. Команда clean останавливает контейнеры и удаляет папку site. Команда shell открывает интерактивную сессию внутри контейнера.

## Создание документации

В папке docs создаются файлы с расширением .md. Основная страница — index.md. Для примеров создаются страницы getting-started.md и api.md. Для вставки кода используются fenced code blocks. Язык программирования указывается после открывающих трёх обратных кавычек. Для отображения названия языка над блоком добавляется атрибут title="название". Например, для bash-команд указывается title="bash". Для Python-кода — title="python".

## Локальный запуск

Сборка образа выполняется командой docker-compose build. Запуск сервера разработки — docker-compose up. Сайт становится доступен по адресу http://localhost:8001. При изменениях файлов сайт пересобирается автоматически. Остановка сервера — Ctrl+C или docker-compose down.

## Инициализация Git

В папке проекта выполняется git init. Создаётся первый коммит со всеми файлами через git add . и git commit -m "Initial commit". На GitHub создаётся новый публичный репозиторий без README, .gitignore и лицензии. Локальный репозиторий связывается с удалённым через git remote add origin. Ветка переключается на main и выполняется git push -u origin main.

## Настройка GitHub Actions

В папке .github/workflows создаётся файл deploy.yml. Workflow активируется при пуше в ветку main и может быть запущен вручную. Ему даются разрешения на чтение содержимого, запись страниц и создание токенов. В задаче build используется ubuntu-latest. Происходит клонирование репозитория, установка Python версии 3.11, установка зависимостей mkdocs и mkdocs-material, сборка сайта командой mkdocs build --clean. Артефакт из папки site загружается для последующего деплоя. Задача deploy запускается после успешной сборки в окружении github-pages. Используется действие deploy-pages для публикации на GitHub Pages.

## Настройка GitHub Pages

В настройках репозитория на вкладке Pages в разделе Build and deployment выбирается источник GitHub Actions. Настройка сохраняется автоматически. После первого пуша или ручного запуска workflow сайт становится доступен по адресу https://имя-пользователя.github.io/название-репозитория.

## Рабочий процесс

Локально вносятся изменения в файлы документации. Для проверки запускается сервер разработки. После завершения правок изменения добавляются в Git с осмысленным сообщением и пушатся в ветку main. GitHub Actions автоматически запускает сборку и деплой. Через 1-2 минуты сайт обновляется.

## Полезные команды

- make serve — запуск локального сервера.
- make build — сборка статической версии.
- make clean — очистка артефактов.
- docker-compose logs — просмотр логов контейнера.
- docker exec -it mkdocs-mkdocs-1 /bin/bash — вход в контейнер для отладки.

## Решение типичных проблем

Если порт 8000 занят, в docker-compose.yml меняется порт на хосте, например, 8001:8000. Если сайт не обновляется, помогает очистка кэша браузера или команда mkdocs build --clean внутри контейнера. Если не отображается язык в блоках кода, к блоку добавляется атрибут title="название". При ошибках деплоя статус проверяется во вкладке Actions на GitHub.

## Примечания

GitHub Pages бесплатен для публичных репозиториев. Предупреждения о Node.js в Actions не влияют на работу и будут исправлены обновлением действий. Проект полностью готов к использованию и масштабированию.
